# 🏀 投篮姿态分析

拍一段自己的投篮视频，几分钟后拿到一份动作报告：你的下蹲、出手、跟随各是什么样子，哪些地方值得留意，以及一份只存在你自己手机里的训练档案。

## 这是什么

这是一个跑在**手机浏览器**里的投篮动作分析工具。你上传（或直接拍摄）一段自己投篮的视频，它会：

- 逐帧识别你的身体骨架，摆出手臂和腿的角度；
- 自动找到你「出手」的那一瞬间，并比较你连投几次的结果；
- 给出 24 项动作指标（角度、时序、平衡、速度……），每一项都用人话解释它在量什么；
- 标出哪些地方明显偏离、哪些只是小偏差；
- 把结果存成训练档案，看得见自己是在进步还是退步。

它是**动作形态筛查**，不是命中率预测，也不是职业教练的替代品。它告诉你「你的出手是直的还是歪的」，至于怎么改，那是你和你的教练的事——这个工具只讲原因，不给训练方法。

## 30 秒上手

1. **打开网址**（手机浏览器直接访问即可，也可以「添加到主屏幕」当 App 用）。
2. **选一段视频**：按第 1 步的拍摄清单拍一段，10–30 秒、连投 3–5 次最好。
3. **点「开始分析」**，等十几秒，报告出来。

第一次打开需要下载约 **25MB** 的识别模型（模型和推理引擎都随站点自托管，从本站下载，不走国外 CDN）；下载完之后会被浏览器缓存，**之后可以完全离线使用**。手机浏览器一样能用，只是分析速度比电脑慢一些。

拍之前建议先看一遍第 1 步的「📹 怎么拍才准」清单——那 6 条直接决定读数准不准。分析完如果素材不合格，报告会直接告诉你哪里不合格、该怎么重拍，而不是照样给你一份看起来很正式的分数。

## 隐私：你的视频和档案只在你自己的设备上

**视频从头到尾不会离开你的浏览器。** 没有服务器、没有账号、没有任何上传——识别是在你手机上跑完的，你的训练档案也存在这台设备的浏览器存储里。

正因为如此，有一件事得说清楚：**换设备、换浏览器，或者清了浏览器数据，档案就没了。** 它不是云端备份，只是本机的一份数据。

所以建议每隔一段时间，在页面底部「6. 训练档案」里点一次 **⬇️ 导出**，存一份 JSON 文件（可以发给自己、在另一台设备导入）。这是我们能给你的最实在的备份方式。

## 读数准不准（说实话）

这个工具的读数可信到什么程度？下面是实话，没有藏起来的免责声明：

- **它量的是动作形态，不是命中率。** 报告里的每一个数字都来自 2D 骨架估算——视频里你的关节在哪儿。骨架对了，角度就对了；骨架没测准，角度就会偏。中间还有透视畸变、人体遮挡、2D 投影这些固有误差。
- **24 项指标里，有 11 项是「趋势参考」。** 它们在运动学上可测，但没有足够可靠的专项文献阈值，所以**不计分、不给结论**，只能在你自己的训练档案里看变化——比如「这一个月你的左右腿发力差是变大了还是变小了」。剩下 13 项有明确区间，报告才会判定达标 / 待改进 / 需纠正。
- **不同机位能测到的项目不一样。** 侧面机位看得见前后方向（下蹲多深、出手角度、上身往前还是往后倾），但**测不到**肘子往外撇、站距、左右对称这类左右方向的指标；正面机位正相反。想看全 24 项，需要补拍另一个机位，在「4. 多角度融合」里合并成一份完整报告。
- **分数不能跨报告、跨版本比较。** 分数只对「这一次、这一份报告」负责。换机位、换投篮类型、换版本，计分口径和权重都不同，两个数字没有可比性。
- **分数环不是成绩单。** 顶部的 0–100 和 S/A/B/C/D 只是这次读数的汇总刻度，别拿去和别人比。

一句话版本：**这个工具能告诉你「哪里不一样」，但它不能告诉你「你行不行」。**

## 常见问题

**Q：手机拍出来，为什么读数不准？**

A：绝大多数情况是拍摄条件的问题，不是你的动作问题。第 1 步的「📹 怎么拍才准」清单列了 6 条最容易踩的坑：手机要横平竖直、全身入镜且人至少占画面高度的三分之一、画面里只有你一个、光线够别逆光、连投 3–5 次、视频别超过 30 秒。分析完如果素材不合格，报告顶部会直接告诉你哪一条没做到、下次该怎么重拍——那种情况下我们**不会**给你分数，因为分数在这里只是噪声。

**Q：为什么我只有一半指标？**

A：因为你只拍了一个机位。侧面机位测不了肘内外展、双脚站距、左右重心这些左右方向的指标；正面机位测不了下蹲膝角、出手方向角这些前后方向的指标。报告底部的「📷 补拍建议」会告诉你缺哪一类，按示意图补拍一段传到「4. 多角度融合」，系统会按「每个指标取最合适的机位」合并成一份完整报告。

**Q：我的数据存在哪？**

A：只存在你这台设备的浏览器里（localStorage），视频压根不会被存下来。没有服务器、没有账号。**清浏览器数据或换设备会丢**，记得用「6. 训练档案」里的导出功能备份。

**Q：能分享给别人吗？**

A：可以。报告页直接截图就行——指标名旁边的 ⓘ 点开是白话解释，报告底部有术语表，截图发群里对方也看得懂。也可以把整个训练档案导出成 JSON 发给别人（对方在自己设备上导入即可）。

**Q：为什么有的指标写着「趋势参考」？**

A：那些指标没有可靠的专项文献阈值可以直接判「好不好」，硬判会误导人，所以只记数值、不计分。攒够几次记录后，在训练档案的「单指标趋势」里看它自己的变化曲线更有意义。

# 🛠 给开发者

以下内容面向想改代码、跑测试或自己部署的人。

## 功能清单

- 手机/电脑选择或拍摄视频
- MediaPipe 姿态识别（33 个关键点），逐帧扫描
- 播放时叠加：骨架、关键点、肘/膝实时角度
- 自动选择面向镜头的一侧（侧面机位）
- 自动检测出手周期（支持一段视频多次出手）：站姿 → 下蹲 → 出手 → 跟随动作；逐次计算后**逐指标取中位数**，更准也更稳（同视频重复分析评分不再漂移）
- 侧面指标 13 项：下蹲膝角、举球肘角、出手肘伸展、出手方向角、出手高度、跟随动作、躯干倾斜、头部晃动、重心横移、起跳（按类型评判）、出手伸肘速度、腿臂分离时差、下肢发力顺序差；其中下蹲膝角、出手方向角、躯干倾斜的评分区间已按投篮科研实测数据校准，出手高度按「有没有离地」用两套区间（见下），另有 4 项场景专属指标（见下）、2 项两机位通用的速度指标（出手垂直速度、起跳上升速度）与 5 项正面指标（肘内外展、双脚站距、左右重心偏移、双膝角度差、躯干侧倾）——共 24 项；其中 11 项是趋势参考型（腿臂分离时差、下肢发力顺序差、左右重心偏移、4 项场景专属、出手垂直速度、起跳上升速度、双膝角度差、躯干侧倾），不计分、不出建议，只靠训练档案的历史趋势看变化
- **术语白话化（v5.8）**：24 项指标各配一句「在量什么」和一句「为什么值得看」（`js/glossary.js`），报告里点指标名后的 ⓘ 就地展开，不做 hover 提示（截图发群时悬停提示并不存在）；报告底部附本次实际出现过的指标术语表；单位与参考区间也补了一句人话（数值本身的呈现格式不变）
- **拍摄清单 + 素材质量预检（v5.8）**：第 1 步新增可勾选的「📹 怎么拍才准」清单（纯行动提示，不持久化、不参与判定）；扫描完成后由 `js/quality.js` 评估素材（人像占比、人体高度占画面比例、关键点可见度、出手周期数、画面人数），**不合格就不出评分报告**，改为一张「这段素材还读不出结果」的重拍指引卡；只是有瑕疵时照常出报告，但报告顶部加黄色提醒
- 出手高度改用「视频级体高尺度」归一化：分母取全程所有有效帧的 (肩y−踝y) 的 90 分位，不再取站姿帧那一帧——出手帧与站姿帧来自不同时刻（正面机位下出手前朝镜头走近会让出手帧尺度偏大），站姿帧若取到屈膝没伸直的状态还会把分母压小，两处叠加会让读数系统性偏高
- 出手高度的判定区间按「这一次出手有没有离地」自适应，不再一刀切：有起跳（跳投/移动投篮）用 **1.05–1.30×身高**（文献实测出手手高为身高的 112.8%–118.9%，取宽区间容纳个体差异），下缘 0.95 是提醒带；不起跳（定点罚球/原地举球）用 **0.75–1.00×身高**（出手点停在肩高，踝→腕的垂直距离只有约 0.75–0.95 个体高），下缘 0.68 是提醒带——拿跳投区间去判点罚球，会把完全正常的肩高出手判成「明显偏低」
- 关键点漂移过滤：MediaPipe 在球挡住手或短暂遮挡时会把腕/肘等关节甩到别处（实测真人素材里腕部在 1/30 秒内跳了 0.369 归一化坐标，该帧体高只有 0.28–0.43，即 1 帧移动约 1.3 个体高 ≈ 40 m/s，物理上不可能），现按「逐帧位移 > 0.6 个体高」判为定位漂移并做插值修补——这是读数可信度的前提；速度类指标（出手垂直速度、起跳上升速度）也改为取窗口中位数而非最大值，单帧尖峰不会把读数带偏
- 跳投 / 罚球 / 三分三种标准切换（罚球要求贴地发力，跳投/三分要求起跳）
- 0–100 评分 + S/A/B/C/D 评级 + 按重要性排序的「问题与原因」（含实测值；点击建议卡可回看视频里出问题的瞬间）
- 关键动作曲线：报告里画出代表性出手的肘角/膝角逐帧曲线（x 轴是相对出手帧的秒数），并标出下蹲/举球/出手/跟随四个关键节点
- 多人同框自动锁定主人公（位置 + 体型双因子跟踪），路人不干扰分析；主人公离开画面时冻结等待、绝不把锁交给旁人
- 人物离场/遮挡的空档不会伪造出手：出手候选必须有真实骨架支撑，站姿基线只取真实帧；无法测量的出手计入「未计入」并在报告中说明原因
- 投篮类型默认自动识别（按是否起跳区分罚球/跳投类），也可手动选跳投/中投/三分/罚球
- 场景拓宽（实验性）：自动判定「定点站投 / 移动后出手 / 接球即投」，可在第 2 步手动指定；移动场景额外给出出手前移动距离与移动速度、起跳-出手时序，接球即投额外给出沉球量——这几项没有文献锚点，只作趋势参考
- 个人资料（身高/体重/年龄）存本机浏览器，显示在报告中，不离开设备
- 训练档案：每次分析自动存到本机（localStorage），报告里显示「较上次」对比，档案区可看评分历史曲线、单指标趋势（带该指标的 good 参考带）、逐条记录（可展开/删除），并支持 JSON 导出/导入到其他设备
- 多角度分析：自动判别机位（侧面/正面/斜侧），报告附「补拍建议」和俯视机位示意图；正面指标 5 项（肘内外展、双脚站距、左右重心偏移、双膝角度差、躯干侧倾）
- 多视频融合：补拍其他机位上传，每个指标自动取最合适的机位，合并成一份完整报告（每项标注来源机位）
- 双视频对比：上传教练/球星参考视频，DTW 逐帧对齐同步播放 + 逐关节偏差分析
- PWA：添加到手机主屏幕当 App 用；二次访问离线可用（模型已缓存）
- 测量按视频宽高比校正：竖屏手机视频的角度/距离不再失真
- HEVC(H.265) 视频自动识别：微信高清视频解不了码时直接说明原因，并给出免费解决办法（VLC / 格式工厂 / iPhone 兼容模式）

## 本地运行

这是纯静态网站，**必须用 `http://` 方式打开**——直接双击 `index.html` 会因 ES 模块限制整体失效（页面会显示红色警告条）：

**方式 A：双击启动脚本（最简单）**
双击项目文件夹里的 `启动本地测试.bat`：自动启动本地服务器并打开浏览器。
它跑的是 `node server.mjs`（零依赖）；想停服务器就关掉最小化的 "shot-analyzer-server" 窗口。

**方式 B：命令行**
```bash
node server.mjs         # 需要装过 Node.js，然后打开 http://127.0.0.1:5500/
# 或
npx -y serve .
# 或
python -m http.server   # 需要装过 Python
```

**方式 C：VSCode Live Server 插件**
安装 "Live Server" 插件后，右键 `index.html` → "Open with Live Server"。

本地开发模式（server.mjs）会屏蔽 `sw.js`，不注册 Service Worker——改完代码刷新即是最新，不会被旧缓存坑到。

识别模型与推理引擎（约 25 MB）已随站点**自托管**（`model/` + `vendor/`），首次打开从本站下载——国内手机网络也能直连，无需访问国外 CDN；之后由 Service Worker 缓存，离线可用。

## 部署到手机可访问（免费）

**方式一：git 命令行（推荐——本机仓库已提交好，两条命令即可推）**
```bash
cd shot-analyzer
git remote add origin https://github.com/<你的用户名>/shot-analyzer.git
git push -u origin main
```
推送时浏览器会弹 GitHub 授权窗，点一下即可。然后开 Settings → Pages → Branch 选 `main` / root → Save，约 1 分钟后访问 `https://<你的用户名>.github.io/shot-analyzer/`。手机浏览器打开 → 分享/菜单 → "添加到主屏幕"，即可像 App 一样离线使用。

**方式二：GitHub 网页上传（不装任何工具）**
1. 注册/登录 GitHub → 右上角 + → New repository，名称如 `shot-analyzer`，选 Public → Create
2. 在空仓库页点 "uploading an existing file"
3. 把本项目**所有文件**（保持文件夹结构）拖进上传区 → Commit changes
   （最大单文件是 `vendor/wasm/` 下两个约 9.4 MB 的 WASM，均在网页上传 25 MB 上限内）
4. 仓库 Settings → Pages → Branch 选 `main` / root → Save
5. 约 1 分钟后访问 `https://<你的用户名>.github.io/shot-analyzer/`

```
    ├── charts.js   零依赖 SVG 图表（关键动作曲线、档案趋势图）
    ├── history.js  训练档案存储层（读写/导出导入/趋势与对比）
    ├── glossary.js 指标术语白话化（每项指标的 say/why + 单位白话）
    ├── quality.js  素材质量预检（人像占比/人体高度/可见度/周期数/人数）+ 拍摄清单
    ├── report.js   评分规则引擎 + 中文建议 + 报告渲染
    ├── compare.js  双视频对比：归一化 + DTW 对齐 + 逐关节偏差
    └── app.js      主流程：选视频 → 扫描 → 质量预检 → 报告 → 多角度融合 → 对比
```

### 真实素材端到端验证（tools/e2e-real.mjs）

合成测试验证不了真实拍摄里的定位漂移与透视畸变，这一步用真人素材跑完整流程：

```bash
node tools/e2e-real.mjs <视频文件名> [站点地址]
# 例如 node tools/e2e-real.mjs _v1.mp4 http://127.0.0.1:5500/
```

前提：本地服务器已启动（`node server.mjs`，端口 5500 起顺延），视频文件放在**站点根目录**下（工具用 `fetch` 从站点取，不走本地文件协议，因此素材不离开本机、也没有跨域限制）。工具用无头 Edge + Chrome DevTools Protocol 驱动页面：注入视频 → 点分析 → 跑完后把报告里的指标读数、结论、训练档案记录数和控制台输出打印出来。Edge 路径可用环境变量 `SHOT_EDGE` 指定，端口用 `SHOT_CDP_PORT`。

工具只接受视频文件名参数，**仓库里不含任何用户视频或用户数据**。

## 拍摄建议（直接影响识别质量）

应用里第 1 步有一份可勾选的清单（`js/quality.js` 的 `SHOT_CHECKLIST`），这里同步一份：

- 手机固定不动（靠墙/支架），位于投篮者**侧面**（垂直于出手方向），不要手持跟拍
- 全身入镜（头顶到脚都可见、至少占画面高度的三分之一），画面中只有一个人
- 光线充足均匀、不逆光，背景干净，拍摄中不要变焦
- 一段视频包含 **1–5 次完整出手**效果最好（系统逐次检测、取中位数）；每次出手之间站直停顿 1–2 秒
- 时长 3–30 秒（更长只分析前 30 秒）；60fps 更佳

分析完成后 `js/quality.js` 会自动核对上面几条：不合格就不出评分报告，只给重拍指引。

## 路线图

- **M1**：上传视频 + 骨架叠加播放 + 基础角度 ✅
- **M2**：投篮周期检测、生物力学指标、评分与中文报告 ✅
- **M3**：参考视频 DTW 对比、PWA 离线、部署指引 ✅
- **M4**：机位自动判别、补拍建议与机位示意图、正面指标、多视频融合报告 ✅
- **M5**：指标加深（出手伸肘速度、腿臂分离时差、下肢发力顺序差、关键动作曲线）✅
- **M6**：训练档案（纵向追踪）：较上次对比、评分历史、单指标趋势、导出/导入 ✅
- **M7**：场景拓宽（定点站投 / 移动后出手 / 接球即投 + 4 项场景专属指标）⚠️ 实验性
  —— 场景判定尚未用真实素材校准：仓库里没有真实视频，判定阈值与场景专属指标区间都只经过合成骨架验证，移动/接球场景的结论仅供参考
- **M8**：出手高度归一化修正（分母改用视频级体高尺度）+ 正面机位指标扩容（出手垂直速度、起跳上升速度、双膝角度差、躯干侧倾）✅
  —— 4 项新指标都是趋势参考型（无可靠专项文献阈值，不计分、不出建议），靠训练档案的历史趋势看变化
- **M9**：出手高度区间按「有没有离地」自适应（起跳 1.05–1.30×身高 / 不起跳 0.75–1.00×身高）+ 关键点漂移过滤（逐帧位移 > 0.6 个体高即判为定位漂移并插值修补）+ 离线壳补全（sw.js 补齐 v5.5 新增的 js 模块、缓存名升 v5.7、应用外壳走 stale-while-revalidate、模型与 WASM 保持 cache-first）✅
  —— 出手高度的两套区间各有依据：跳投按文献实测出手手高 112.8%–118.9% 校准，不起跳的定点出手按「出手点在肩高、踝→腕只有 0.75–0.95 个体高」校准，混用会把正常的肩高出手判成偏低
- **M10**：面向普通球友的上手改造——第 1 步拍摄清单 + 素材质量预检（不合格不出评分报告）+ 指标术语白话化 + README 门面重写 ✅
  —— 这一轮**没有动任何指标算法**：区间、阈值、打分口径全部保持 v5.7 的样子，改的只有「怎么拍、怎么读、怎么讲清楚」

## 已知限制

- 视频编码需浏览器支持：HEVC(H.265)（微信高清视频常用）在缺解码器的浏览器上无法分析，应用会检测出来并给出免费转换办法
- 出手瞬间球/手移动极快，建议 60fps 拍摄、光线充足、手机固定
- 单机位存在视角盲区（侧面看不到肘内外展/左右对称，正面看不到矢状面指标）；应用会自动判别机位并提示补拍，多视频融合可补全
- 参考对比需要用户自备参考视频（教练示范或球星片段），应用不内置盗版素材
- 手机浏览器推理约 15–30 fps，5 秒视频分析约需 10–30 秒
- 训练档案只存在本机浏览器（隐私模式下无法保存，只能用导出/导入迁移）；清除浏览器数据会一并清空档案
- 移动/接球场景判定是实验性功能：场景判定尚未用真实素材校准，场景专属指标（出手前移动距离/速度、起跳-出手时序、沉球量）也没有文献锚点，只作趋势参考，报告底部会给出醒目提示
- 出手高度的分母已改为「视频级体高尺度」（全程 (肩y−踝y) 的 90 分位），但真实素材的校准仍在积累中：正面机位的透视畸变、画面裁切与多人同框都会影响读数。判定区间现在按「这一次出手有没有离地」分成两套并存——有起跳（跳投/移动投篮）用 1.05–1.30×身高，**不起跳的定点出手（罚球/原地举球）用 0.75–1.00×身高**；两套区间的读数都建议结合侧面机位复核
- 关键点漂移过滤只能拦住明显的定位错误（逐帧位移超过 0.6 个体高）：球长时间挡住手、大面积遮挡等情况下，残留的小幅误差仍会进到读数里，此时以侧面机位复核为准
- 出手垂直速度、起跳上升速度、双膝角度差、躯干侧倾这 4 项新指标只有合成骨架验证，没有真实素材校准，也没有专项文献阈值，只作趋势参考
- 素材质量预检（v5.8）的阈值同样是经验值：它只能挡住「明显拍坏」的素材，无法判断一段素材到底准不准，只能提示风险
- 术语白话化（v5.8）是给第一次用的人看的通俗解释，不是运动科学定义；遇到概念冲突以 `docs/投篮理解.md` 的文献口径为准
